# 미사용/도달 불가 코드·데이터 삭제 검사 규칙

## 목차
1. 목적
2. 적용 시점 (언제 검사하는가)
3. 검사 대상 (무엇을 찾는가)
4. 검증 절차 (삭제 전 반드시)
5. 사용자 승인 절차 (삭제는 검사받는다)
6. 삭제 금지/보류 예외
7. 실행 체크리스트

## 1. 목적

- spec 작업(기능 추가·수정·리팩터링)을 마친 뒤, 그 작업으로 인해 **더 이상
  접근되지 않거나 사용되지 않게 된 데이터·로직**을 찾아내 정리한다.
- 목적은 "죽은 코드(dead code)"가 남아 유지보수를 흐리게 하는 것을 막는 것이다.
- 단, **자동 삭제는 하지 않는다.** 반드시 후보를 정리해 사용자에게 보고하고
  **삭제 여부를 검사받은 뒤** 처리한다.

## 2. 적용 시점 (언제 검사하는가)

- 하나의 spec 작업 또는 응집된 기능 묶음을 **완료한 직후**에 검사한다.
- 특히 아래 작업 뒤에는 미사용 잔여물이 생기기 쉬우므로 반드시 검사한다.
  - 함수/메서드 시그니처 변경, 호출부 교체
  - 분기/조건 로직 재구성 (기존 분기가 도달 불가로 바뀜)
  - 화면·API·쿼리 교체로 기존 것이 대체됨
  - 데이터 모델/컬럼/상수/리소스 키 교체

### 적용하지 않는 경우
- 단순 조회·설명 등 코드를 바꾸지 않은 작업.
- 사용자가 "정리 검사는 생략"이라고 명시한 경우.

## 3. 검사 대상 (무엇을 찾는가)

이번 작업으로 **도달 불가(unreachable)** 하거나 **미사용(unused)** 이 된 항목:

- 호출되지 않는 함수/메서드/이벤트 핸들러
- 참조되지 않는 변수/상수/필드/import
- 도달 불가 분기 (항상 false인 조건, 대체되어 죽은 else 등)
- 더 이상 쓰이지 않는 화면 요소/버튼/그리드 컬럼
- 참조 없는 리소스 키(`.properties` 등), 메시지 번들 항목
- 대체된 쿼리/매퍼/DTO 필드
- 작업 중 만든 임시·디버깅 잔재(주석 처리된 옛 코드 포함)

## 4. 검증 절차 (삭제 전 반드시)

"안 쓰는 것 같다"는 추측으로 삭제하지 않는다. 아래로 **실제 미사용을 입증**한다.

1. `grep_search`로 식별자·키·컬럼명을 **워크스페이스 전역에서 참조 검색**한다.
   (파일 유형/경로를 `includePattern`으로 좁혀 컨텍스트 폭증을 피한다.)
2. 동적 참조 가능성을 점검한다.
   - 문자열로 조합되는 이름(리플렉션, `eval`, 문자열 연결 키 등)
   - 설정/XML/JSP/WebSquare에서의 참조, 외부(다른 화면·배치·잡)에서의 참조
3. 참조가 **0건이고 동적 참조 가능성도 없을 때만** 삭제 후보로 확정한다.
4. 확신이 서지 않으면 삭제 후보가 아니라 **"확인 필요" 항목**으로 분류한다.

## 5. 사용자 승인 절차 (삭제는 검사받는다)

- 검증을 마치면 **삭제 후보 목록을 표로 정리해 사용자에게 먼저 보고**한다.
  임의로 먼저 지우지 않는다.
- 각 후보에 대해 다음을 함께 제시한다.

| 항목 | 위치(파일:라인) | 왜 미사용인가 | 참조 검색 결과 | 삭제/보류 제안 |
|------|----------------|--------------|---------------|---------------|

- 사용자가 **명시적으로 승인한 항목만** 삭제한다.
- 삭제 후에는 빌드/컴파일 등으로 **회귀가 없는지 검증**하고 결과를 보고한다.
- "확인 필요" 항목은 삭제하지 말고 사용자 판단을 요청한다.

## 6. 삭제 금지/보류 예외

아래는 미사용처럼 보여도 **함부로 삭제하지 않는다.**

- 공개 API·인터페이스·라이브러리 export (외부에서 참조될 수 있음)
- 프레임워크 규약상 이름으로 호출되는 항목(리플렉션, 매핑 대상)
- 마이그레이션/롤백·기능 플래그로 곧 다시 쓸 예정인 코드
- 테스트 픽스처·샘플·문서용으로 의도된 항목
- 법적·감사(audit) 목적으로 보존이 필요한 데이터

이런 항목은 삭제 후보가 아니라 **보류로 분류하고 이유를 명시**한다.

## 7. 실행 체크리스트

- [ ] 코드 변경 작업을 완료한 직후 미사용 검사를 수행했는가
- [ ] 후보를 grep 전역 검색으로 참조 0건임을 확인했는가
- [ ] 동적 참조(문자열/설정/외부) 가능성을 점검했는가
- [ ] 확신이 없는 항목은 "확인 필요"로 분류했는가
- [ ] 삭제 후보를 표로 정리해 사용자에게 먼저 보고했는가
- [ ] 승인받은 항목만 삭제했는가
- [ ] 삭제 후 빌드/컴파일로 회귀가 없음을 검증했는가
- [ ] 예외(공개 API·프레임워크 규약 등)는 보류로 분류했는가
