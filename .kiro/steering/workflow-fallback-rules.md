# Workflow 실행 중단 시 직접 수행 규칙

## 원칙
- Workflow(`run_workflow`)나 서브에이전트 위임은 "가능하면 활용"하는 수단일 뿐,
  작업 진행의 필수 조건이 아니다.
- 백그라운드 Workflow 실행이 끊기면, 같은 작업을 **현재 세션에서 지체 없이 직접
  이어서 수행**한다. 다시 위임할지 사용자에게 되묻느라 멈추지 않는다.

## 끊김으로 보는 경우
- `run_workflow` 호출 자체가 실패하거나 즉시 취소됨
- 단계가 `error`로 끝나거나, run이 failed / aborted로 종료됨
- 진행 알림 없이 단계가 멈춰 더 이상 진행되지 않음
- 단, 단계가 `warning`(질문 대기)으로 멈춘 것은 끊김이 아니다. 질문에 답하거나
  사용자에게 전달한다.
- 한 세션에서 한 번이라도 즉시 실패하면, 그 세션에서는 위임이 고장 난 것으로 보고
  이후 작업도 직접 처리한다.

## 직접 수행 방식
- `inspect_workflow`로 끝난 단계와 산출물을 먼저 확인하고, 완료된 부분은 반복하지
  않고 **남은 부분부터** 이어서 한다.
- 조사 단계는 파일 읽기·검색 도구로, 구현·검증 단계는 현재 세션에서 직접 코드를
  작성하고 빌드·테스트한다.
- Workflow가 워크트리를 만들어 쓰던 중이면 그 경로와 브랜치를 그대로 이어서 쓴다.

## 사용자 안내
- 전환할 때는 한 줄로만 알린다.
  (예: "Workflow 실행이 끊겨 남은 작업을 직접 이어서 처리하겠습니다.")
- 반복해서 끊기면 새 세션 또는 IDE 재시작을 권하고, Workflows 설정
  (`kiroAgent.workflows.enabled`)이 켜져 있는지 확인하도록 안내한다.
